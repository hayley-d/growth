# Frontend

React 19 with Vite. TanStack Router (file-based), Query, Form and Table. Zustand for client-only state. Tailwind CSS v4 and shadcn/ui. Axios for HTTP.

## Where things go

```
frontend/src/
  components/
    atoms/        smallest building blocks; shadcn components are generated here
    molecules/    groups of atoms
    organisms/    large sections built from molecules and atoms
    templates/    page layouts with no data
  pages/          templates filled with data; routes render these
  routes/         TanStack Router file routes; thin, render a page
  services/       API calls, one <name>-service/ folder per feature
  lib/
    queries/      TanStack Query hooks, <name>.queries.ts per feature
    mutations/    TanStack mutation hooks, <name>.mutations.ts per feature
    query-client.ts, utils.ts (cn)
  stores/         Zustand stores, one per concern
  config.ts       hostUrl from VITE_API_URL, defaults to /api
  index.css       Tailwind and the theme colours
  main.tsx        mounts the router and query client
  routeTree.gen.ts  generated by TanStack Router, git-ignored, never edit
```

Each of `components/`, `services/`, `lib/`, `routes/`, `pages/` and `stores/` has its own `AGENTS.md`.

Imports use `@/` for `frontend/src` (for example `@/components/atoms/button`) and `@shared/` for schemas.

## How data flows

```
route → page → hook (lib/queries or lib/mutations) → service → networkService (axios) → /api
```

- Components never call services or axios directly. They use a hook.
- Server state lives in TanStack Query. Client-only state (open menus, selected tree, animation speed) lives in Zustand. Never copy server data into a store.

## Adding a feature

1. Schemas in `shared/src/schemas/<feature>.ts` (see `shared/AGENTS.md`).
2. A service folder in `services/<feature>-service/`.
3. Hooks in `lib/queries/<feature>.queries.ts` and `lib/mutations/<feature>.mutations.ts`.
4. Atoms, molecules and organisms you need, then a template.
5. A page in `pages/` that fills the template with hook data.
6. A route file in `routes/` that renders the page.
7. Tests for the service, and for the page or components.

## Mobile first

Every page must work on a phone.

- Write the phone layout first, then add `sm:`, `md:`, `lg:` for wider screens.
- Check every page at 375px wide. No horizontal scroll.
- Touch targets are at least 44px: `min-h-11` or `size-11`.

## Styling

- Plain Tailwind first. Reach for a shadcn component only when it saves real work.
- Use the theme colours from `index.css` (`bg-primary`, `text-muted-foreground`, ...), not raw colour values.
- Join class names with `cn` from `@/lib/utils`.

## Tests

- `*.test.ts` runs in Node. Use it for services, hooks logic and stores.
- `*.test.tsx` runs in real Chromium with Vitest browser mode and `vitest-browser-react`. Use it for components and pages.
- Run `bun run test:install-browsers` once to download Chromium.
- Find elements by role and name (`getByRole("heading", { name: "Growth" })`), not by class or test id.

## Scripts

Run from `frontend/`: `bun run dev` (Vite on port 5173, proxies `/api` to http://localhost:3000), `bun run test`, `bun run typecheck` (generates the route tree first), `bun run build`.

Keep this file current: update it in the same commit when you add a top-level folder, change the data flow or add a script.
