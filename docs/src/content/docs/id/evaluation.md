title: Evaluation
description: How we'd check that the app teaches well.

We tested Growth ourselves as a team, which is covered on the [Alpha and beta](../development/) page. That testing finds bugs, but it can't tell us if Growth actually teaches, because we already know the content. This page describes how we would evaluate Growth with real COS212 students.

## Who we would test with

A small group of COS212 students who haven't had the lecture on trees yet. That matches who Growth is built for, a learner who doesn't know the data structure or the algorithm yet.

## What we would measure

**Learning.** Each student writes a short pre-test before using Growth and a post-test after. Both tests ask questions written against the [learning objectives](../objectives/), so we can see which objectives improved and which didn't. If an objective doesn't improve, that points us at the lesson that teaches it.

**Test results inside the app.** Growth already records every test attempt. We would look at the pass rate for each lesson test and how many attempts it took to pass. A lesson that most students fail the first time is either too hard or doesn't teach what the test asks.

**Hint use.** If most students open all the hints on one question, the question or the lesson before it needs work.

**Time per lesson.** A lesson that takes much longer than the others might be trying to cover too much in one sitting.

**Motivation.** A short survey after using Growth, with questions based on the four parts of Keller's ARCS model that we used on the [Motivation](../motivation/) page: attention, relevance, confidence and satisfaction (Keller, 1987).

**What students tell us.** We would watch a few students use Growth and ask them to think aloud. This shows where they get confused in a way the numbers don't.

## What we would do with it

The results would feed back into SAM. Anything that needs a design change goes back to a storyboard, and anything that is a bug gets fixed in the beta. Once the students' feedback has been worked through, that version would become the gold version.

## References

Keller, J.M. (1987) 'Development and use of the ARCS model of instructional design', *Journal of Instructional Development*, 10(3), pp. 2–10. doi: 10.1007/BF02905780.
